## 使用方式

先用 `scripts/crypto_snapshot.py <SYMBOL>` 取真实数据，然后**按下面的章节结构**写报告。
所有 `{}` 占位符必须用快照真实数字替换；快照 `data_quality.missing_or_degraded` 里的缺口必须在报告中显式标注。

## 铁律（违反即报告作废）

1. **禁止套用股票口径**：加密资产没有财报、没有分析师目标价、没有净资产。禁止出现 PE/PB/ROE、护城河、管理层评分、分析师一致预期等股票概念。**没有数据就写"无数据"，绝不因为"应该有个基本面"而编造。**
2. **价格与仓位结论只以交易所 API 为准**：聚合源（dogdoing 等）的价格仅用于交叉校验；偏差 >1% 时以交易所价为准并在报告标注。
3. **资金费率必须区分正负**：正费率=多头付钱给空头（多头拥挤）；负费率=空头付钱给多头。必须给出年化口径与历史正向占比。
4. **杠杆必须做爆仓距离校验**：`强平距离 ≥ 1.5 × 止损距离`，否则该杠杆不可用。杠杆是强平距离的决定项，不是收益放大器。
5. **清算聚集区标注为代理指标**（无免费清算明细接口）：结构极点 + 高量成本区 + 整数关口。
6. **24/7 市场没有"隔夜缺口"概念**，但**有低流动性时段**（周末与 UTC 凌晨）：开仓规模必须参照滑点模拟与分时段成交量折减。
7. **数字审计必跑**：`scripts/audit_memo.py` 对账快照，抓编造与陈旧数字。

### 第 5 章 · 多空激辩（围绕资金面与技术面，不涉财报）

**看跌论点**：结构为"我们建议规避 {SYMBOL}，核心风险在于 {最不利的资金面/技术面证据，如 4H RSI 超买 + 社交热度居前 + 资金费率正分位高}，这在 {技术证据} 中亦有体现。虽然多头强调 {其核心优势}，但该优势脆弱或已被高估，因为 {具体原因}。"

**要求**：多空双方必须**直接反驳对方的核心论据**；每条论据必须引用快照中的具体数字。**禁止用"项目基本面良好/生态繁荣"这类无法量化的说法充当论据。**
